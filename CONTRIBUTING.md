# Внесок у «Балачки» / Contributing to Balachky

Дякуємо за бажання допомогти! Проєкт розробляється й підтримується автором одноосібно, тому зрозумілі, чіткі повідомлення та пропозиції дуже цінуються.

Thanks for wanting to help! This project is maintained solely by the author, so clear and concise reports or suggestions are hugely appreciated.

---

## 🇺🇦 Для користувачів та дописувачів

### Як повідомити про баг або запропонувати ідею
- **Повідомити про баг:** Відкрийте вкладку **Issues** і натисніть **New issue → «Повідомити про баг»**. Заповніть підказки у формі.
- **Запропонувати функцію:** Відкрийте **Issues → New issue → «Запропонувати функцію»** або створіть тему у **Discussions**.
- **Запропонувати слово у словник:** Якщо хочете додати термін чи виправлення розпізнавання, напишіть у **Discussions** або створіть **Issue**.

### Чого НЕ треба робити
- **Не викладайте приватні аудіозаписи та розшифровки.** Ніколи не додавайте до Issue чи Discussions голосові записи, стенограми чи текстові чернетки з особистою чи робочою інформацією.
- **Не викладайте особисті дані чи ключі.** Перевіряйте журнали (логи) перед прикріпленням.
- **Не дублюйте вже наявні Issue.** Пошукайте перед створенням нового запиту.

### Внесок коду (Code Contributions)
Програма поширюється за некомерційною ліцензією **PolyForm Noncommercial 1.0.0** (файл `LICENSE`) з додатковими дозволами (`COMMERCIAL-LICENSE.md`). Щоб автор міг і надалі надавати комерційні дозволи та зберігати цілісність проєкту, **увесь код має лишатися у власності автора**.

Тому діють такі умови:
1. Зовнішні Pull Requests із кодом зараз **не приймаються**: проєкт веде одна людина, а ліцензія некомерційна, тож юридичну машинерію навколо внесків заводити передчасно.
2. Простіший і рекомендований шлях — **не надсилати код у PR**, а описати ідею чи виявлений баг у **Issues/Discussions**. Це найзручніший і найкорисніший внесок.
3. Проєкт не надає гарантованих строків розгляду (SLA): автор читає Issues і Discussions за першої можливості.

## 🇬🇧 For Users & Contributors

### Reporting Bugs & Requesting Features
- **Report a bug:** Open the **Issues** tab and click **New issue → "Bug report"**. Fill in the template fields.
- **Suggest a feature:** Open **Issues → New issue → "Feature request"** or start a topic in **Discussions**.
- **Suggest dictionary words:** Post in **Discussions** or open an **Issue** with the word, spelling, and context.

### What NOT to do
- **Do not post private audio or transcripts.** Never attach voice recordings or meeting minutes containing confidential or personal data.
- **Do not include secrets or personal info.** Check your log files before attaching them.
- **Do not create duplicate Issues.** Search existing reports first.

### Contributing Code
The software is distributed under the **PolyForm Noncommercial 1.0.0** license (`LICENSE`) with additional permissions (`COMMERCIAL-LICENSE.md`). To allow the author to issue commercial permissions and maintain project integrity, **all code ownership remains with the author**.

Conditions for code contributions:
1. External code Pull Requests are **not accepted at the moment**: the project is maintained by one person under a noncommercial licence, so setting up the legal machinery around contributions would be premature.
2. The recommended path is **not to submit code PRs**, but rather describe the bug or feature idea in **Issues/Discussions**.
3. There are no guaranteed response times (SLA): the author reads Issues and Discussions when possible.
