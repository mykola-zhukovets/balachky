# QA-ГЕЙТ «Балачки»

> **Мантра: зелені юніт-тести ≠ працює.**
> 660 зелених тестів не спіймали ні краху live-dictation, ні nav-багу «Запис
> екрана → Історія», ні ImportError діаризації. Діагностика працювала —
> провалився **конвеєр**: знахідки не блокували білд. Цей гейт робить кожну
> знахідку блокером.

## Принцип

**Червоний пункт будь-якого рівня → білд не робиться і не віддається.** Після
фіксу гейт проходиться заново **з Рівня 0** (фікс міг зачепити щось раніше
зелене). Кожен дефект, що просочився повз гейт, закривається **лише разом із
тестом/пунктом гейту, що його відтворює** — статус «→ виправить
розробник» без тесту = не закрито.

Рівні 0-2 автоматичні (`dev/qa_gate.ps1`). Рівень 3 — після успішного білда.
Рівні 4-5 — руками, результат у `LOG_WORK.md`.

```
pwsh -File dev\qa_gate.ps1            # Рівні 0-2 (dev)
pwsh -File dev\qa_gate.ps1 -Frozen   # Рівень 2 на dist\Balachky\Balachky.exe
```

## Рівень 0 — статика (~1 хв, авто)

| Крок | Інструмент | Що ловить | Провал |
|---|---|---|---|
| 0.1 | `pyflakes fronts\desktop whisper_core` | невикористане, зламані посилання, undefined | будь-який вивід |
| 0.2 | `dev\check_lazy_imports.py` | **зниклі імена в імпортах, у т.ч. ЛІНИВИХ** (усередині функцій) | `код ≠ 0` |
| 0.3 | `compileall -q fronts whisper_core` | синтаксис усіх модулів | `код ≠ 0` |
| 0.4 | `pyright` (якщо є) | `reportAttributeAccessIssue` (спіймав би `set_live_sink`) | помилки типів; **немає pyright → жовте, не червоне** |

**Чому окремий `check_lazy_imports.py`, а не лише pyflakes.** Історичний баг —
`from .settings import DiarizationDownloadWorker` усередині методу, коли клас
уже видалили. pyflakes бачить лише невикористаний імпорт, а не **зникле ім'я**;
лінивий (in-function) імпорт не виконується, поки не клікнеш саме ту кнопку.
Сканер робить AST-обхід **усіх** import (у функціях, методах, `if`, класах),
реально імпортує кожен модуль **і** перевіряє `hasattr` для кожного імені.
Пропускає (списком «пропущено», прозоро): optional у `try/except ImportError`
та платформенні розвилки `if os.name == "nt": … else: import fcntl`.

## Рівень 1 — юніт + smoke (~3-5 хв, авто)

| Крок | Команда | Нотатка |
|---|---|---|
| 1.1 | `unittest discover -s tests` | повний набір (патерн `test*.py`) |
| 1.2 | `unittest tests.render_*_smoke` | КОЖЕН окремим процесом (динамічно) |

**Чому render-smoke окремими процесами.** Це єдині тести, що будують ЖИВІ
QWidget із таймерами (LevelMeter 30fps, `_tick` 1s). У спільному процесі з
рештою набору недобитий Qt-таймер під час static-деструкції offscreen-Qt на
виході давав флакі-краш `0xC000041D` **після** «OK». Тому вони поза `discover`
(патерн `render_*.py` не матчить `test*.py`) і йдуть окремими процесами.
Наскрізний покажчик:
- `render_clickthrough_smoke` — **Рів.2.1**: реальний `QTest.mouseClick` по
  кожній з 7 кнопок сайдбара → правильний індекс **і** клас сторінки.
- `render_nav_smoke` — порядок стека = порядок навігації; стани бейджа.
- `render_meeting_smoke` / `render_*_smoke` — рендер відповідних вкладок.

Правило: **кожен live-дефект Миколи отримує регресійний тест** тут.

## Рівень 1.5 — візуальний гейт: обрізання + кольори (~20-30 с, авто)

`scripts\visual_gate.py` будує **ЖИВЕ** вікно (платформа `windows` — offscreen
бреше про системні шрифти) і геометрично перевіряє кожен текстовий/іконковий
контрол на всіх 7 сторінках і досяжних діалогах, обома мовами (uk/en), на
трьох ширинах вікна (1000 мінімум / 1280 ноутбук / 1856 «перегляд 1920» —
вузьке навмисно, бо саме там різалось те, чого широке вікно не показує).

| Крок | Команда | Що ловить | Провал |
|---|---|---|---|
| 1.5a | `visual_gate.py --selfcheck` | детектор не пустушка (синтетична обрізана кнопка МУСИТЬ зловитись) | будь-яка з 8 самоперевірок не пройшла |
| 1.5b | `visual_gate.py --strict` | обрізаний текст / іконка / накладання **поза** `visual_gate_baseline.json` | нове порушення |

**Колір інтерфейсу — персоналізація, не декор (рішення власника 25.07).**
`fronts/desktop/theme.py` дає вибір кольору (`classic`/`red`/пресети
`amber/green/teal/blue/purple/pink`/довільний тон 0-359 —
`theme.PRESETS`/`build_palette_for_hue`); кожен варіант — це нова таблиця
кольорів тексту, рамок і скла (геометрія в усіх однакова, `--strict`-крок
вище її вже покриває на класиці). Гейт ганяє `--strict` **ще на двох
кольорах** (BALACHKY_UI_COLOR=red і =teal — еталонний і один з нових
пресетів; middle ground між «жодного кольору не перевірили» і «ганяти всіх
8 щоразу») — інакше нечитний текст на нестандартному кольорі проходив би
непоміченим, як довгий час проходив нічний/червоний до 25.07. Змінна
середовища читається `theme.py` **на імпорті модуля**, тому кожен колір —
окремий процес python; старий `BALACHKY_FORCE_NIGHT=1` (= `red`) лишається
робочим для сумісності. Класичний прогін пише звіт у
`scripts\visual_gate_report.json` (як і завжди), інші кольори — у
`visual_gate_report_<колір>.json` (не затирають один одного, обидва —
регенеровані артефакти, у git не йдуть).

## Рівень 5 — візуальна/UX-верифікація за рубрикою (VLM-суддя, ~10-15 хв)

Причина: візуальна перевірка двічі
провалювалась — «дивились у код», offscreen брехав про шрифти.
Тому — тверда рубрика, а не «глянь чи гарно».

**Принципи.**
1. **Лише реальне вікно на екрані** (DWM/DirectWrite). Offscreen — тільки «чи
   запускається», НІКОЛИ для вигляду. Фінальні кадри — **живий frozen
   `Balachky.exe` на 1920** (канон Миколи).
2. **Рубрика, не смак.** VLM-суддя надійний рівно настільки, наскільки чітка
   рубрика; вивід — **структурований JSON** pass/fail/na з доказом, не вільний
   текст. Кожен пункт **бінарний**, з прикладом fail у промті судді. **Один
   кадр за раз.**

### 5.1 Скріншот-пакет (лише живе frozen-вікно)
- [ ] 7 сторінок на **1920** (канон Миколи); за потреби ще **100/125/150%** DPI;
- [ ] стани Блоку 5: **normal / hover / disabled / focus** —
      `scripts\screenshots.py --states` (кадри 08 rec, 09 disabled, 10 focus;
      клієнтська область ~FullHD);
- [ ] **не offscreen** (інакше чужі шрифти).

### 5.2 Рубрика — 19 перевірок
**Блок 1 — текст (P0, блокує гейт):** 1) літери не зрізані рамкою; 2) текст не
виходить за межі кнопки/картки; 3) нема «…» там, де на 1920 мало бути повне
слово; 4) текстові блоки не накладаються.
**Блок 2 — вирівнювання (P1):** 5) елементи ряду/колонки на одній осі (≤2px);
6) однакові за роллю — однакові розміри/відступи; 7) симетричні краї контейнера.
**Блок 3 — читабельність (P1):** 8) контраст достатній (суддя не читає впевнено
→ fail); 9) активний стан відрізняється не лише кольором; 10) плейсхолдер ≠
введене.
**Блок 4 — ієрархія/консистентність (P1):** 11) кегль h1 > підзаголовок > body
строго; 12) однакові дії названі однаково на всіх сторінках; 13) однакові іконки
для однакових значень.
**Блок 5 — стани (P1, кадри normal/hover/disabled/focus):** 14) disabled видимо
«сірий»; 15) focus має видиме кільце; 16) hover змінюється.
**Блок 6 — функціональність (P0):** 17) кожен клікабельний контрол змінює видимий
стан («мертва кнопка» = fail); 18) кожен контрол має непорожнє accessible name;
19) Tab-порядок відповідає візуальному. **Блок 6 — авто на Рів.3.5**
(`render_a11y_smoke`); тут суддя лише звіряє неавтоматизоване (реальний діф стану).

**Пороги.** fail **Блоку 1 або 6** → гейт **червоний**. Блоки 2-5 → **P1-звіт**
Миколі, не блокують автоматично.

### 5.3 Формат вердикту (JSON, `qa-reports/visual-<час>.json`)

Один запис на кожен пункт × сторінку; файл порівнюваний між прогонами:

```json
{
  "build": "28917487",
  "screen": "07-settings",
  "checks": [
    {"id": 2, "block": 1, "priority": "P0", "verdict": "pass",
     "evidence": "усі підписи в межах кнопок, край не торкається тексту"},
    {"id": 8, "block": 3, "priority": "P1", "verdict": "fail",
     "evidence": "підказку сірим по світло-сірому не прочитати впевнено"},
    {"id": 15, "block": 5, "priority": "P1", "verdict": "na",
     "evidence": "кадру focus для цієї сторінки немає"}
  ],
  "gate": "red"
}
```

`verdict` ∈ `pass|fail|na`. `gate`: `red` (є хоч один P0-fail) | `p1-report`
(лише P1-fail) | `green`.

### 5.4 Task-based прохід (cognitive walkthrough)

Суддя йде **скріншотами** (не кодом) і каже, де застряг би новий користувач.
3-5 задач; приклади:
1. «Вимкни звук підтвердження вставки» за **≤3 кліки**.
2. «Додай виправлення слова у словник» — знайти вхід без підказки.
3. «Постав диктування у режим показу у вікні, а не вставки».

Застряг / перевищив ліміт кліків / пункт не знайдено → **P1-звіт** Миколі.

### 5.5 Межі: що ЛИШЕ людина (Микола)

Смак/естетика й затвердження канону · тактильне «чи зручно» наживо (мікрозатримки,
потік диктування) · рішення релізити · живий тест із реальним звуком · періодична
ревізія самої рубрики.

## Черговість (при злитті гілок)

Центральні конфлікти в `app.py`, `session.py`, `postprocess.py`, `settings.py`
зливати **лише послідовно**; після кожного merge — гейт **з Рівня 0**.
PyInstaller запускати лише при `exit 0` Рівнів 0-2.
