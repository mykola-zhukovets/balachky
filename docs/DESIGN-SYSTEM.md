# Канон компонентів і розміщення «Balachky»

Єдине джерело правди для **поведінки кнопок, форм, карток і станів** — «кнопка
відповідає так, розміщення таке». Кольори, шрифт і кеглі НЕ чіпаємо (це
`docs/DESIGN-TYPOGRAPHY.md` і токени `theme.py`) — тут лише **варіанти, розміри,
відступи, вирівнювання, стани**. База — реальний код `fronts/desktop` + Fluent 2
(Windows 11), адаптовані до наявних значень, щоб міграція була еволюційною, а не
рескейлом.

Джерело стилів (QSS): `fronts/desktop/theme.py`. Хелпери форм/карток:
`fronts/desktop/pages/settings.py:116-153`.

Принцип: **різниця ваги дій = різниця варіанта кнопки**, а не колір «на око»;
**вирівнювання = одна вісь**, а не «приблизно в стовпчик»; **відступ = токен із
шкали 4px**, а не випадкове число. Ці три важелі прибирають 90% «кострубатого».

---

## 0. Шкала відступів — 4px-сітка

Усі `setSpacing` / `setContentsMargins` беруть значення з цієї шкали. Fluent 2:
«A 4x system reduces confusion while being easy to implement.»

| Токен | px | Де застосовувати |
|---|---|---|
| `XS` | 4 | щільні колонки, дрібний зазор мітка↔значення |
| `S` | 8 | **типовий gap** між контролами в ряду |
| `M` | 12 | вертикальний крок форми, зазор у групі |
| `L` | 16 | між групами всередині картки, розділювач head |
| `XL` | 20 | нижній відступ картки, колонка налаштувань |
| `XXL` | 24 | горизонтальний зазор сітки форми, широкі колонки |
| page | 32 / 26 / 32 / 18 | зовнішні поля сторінки (root VBox) — див. §2 |

Санкціоновані винятки (Fluent teж їх лишає під іконки/вирівнювання): **2** і **6**
— тільки icon↔text та лейбл↔ⓘ-хінт. Усе інше — **заборонені off-grid значення**:
3, 5, 7, 9, 11, 13, 15, 21, 23 у `setSpacing`. У коді сьогодні лишились 1×`3` і
1×`5` — підлягають прибиранню під час застосування (окрема хвиля).

## 1. Кнопки

### 1.1 Чотири ролі → три QSS-варіанти

У QSS уже є рівно три варіанти (`theme.py:215-232`), заданих Qt-property на
`QPushButton`, без підкласів. Чотири семантичні ролі лягають на них так:

| Роль | Варіант (як задати) | QSS | Коли |
|---|---|---|---|
| **Основна** (primary) | `btn.setProperty("accent", True)` | GOLD-заливка, `TEXT_ON_GOLD`, 600, padding 10×22 | головна дія екрана/діалогу. **Рівно одна** на видимий блок |
| **Другорядна** (secondary) | без property (базова) | DEEP, 1px `_LINE_SOFT`, padding 8×18 | звичайні дії форми («Змінити», «Огляд») |
| **Тиха** (ghost / tertiary) | `btn.setProperty("ghost", True)` | прозора, текст `TEXT_MUTED`, padding 8×12 | дрібні/повторювані дії: «Очистити», «Скинути», інлайн-дії в рядку |
| **Небезпечна** (destructive) | `btn.setProperty("danger", True)` + діалог підтвердження | прозора, тонка теракотова рамка/текст `DANGER_MUTED`, БЕЗ заливки | видалення/незворотне. Див. 1.5 |

**Деструктив = вторинна кнопка зі стриманим danger-відтінком + підтвердження**
(рішення дизайн-власника, аудит Миколи 22.07). Варіант `danger` — прозорий фон,
тонка рамка й текст теплим теракотом `DANGER_MUTED` (`theme.py`, `#CF7B62`), hover —
легкий теракотовий підсвіт. Це **не** «кричуща червона кнопка»: ALERT `#E52421`
(`theme.py:5,24`) лишається зарезервованим ЛИШЕ під запис (REC) і error-бейдж —
у кнопках його не використовуємо. `danger` **завжди** в парі з обов'язковим
`QMessageBox`-підтвердженням (Fluent: «destructive actions use a subtle appearance +
confirmation»); без підтвердження — це базова кнопка, не `danger`.

### 1.2 Розміри й мінімальна ширина ВІД ТЕКСТУ

- Висота: `min-height: 24px` у QSS + padding → фактична ≈40px. Не задавати висоту
  вручну.
- **Ширина = вміст + padding. НІКОЛИ `setFixedWidth` на кнопці.** Кнопка росте під
  свій текст (укр-рядки довші за англ.; фіксована ширина = обрізання при UK). Якщо
  потрібна візуальна рівність кнопок у ряду — вирівнювати layout-stretch'ем, а не
  однаковим фіксованим px.
- Іконка+текст у кнопці: зазор **6px** (виняток шкали), іконка ліворуч.
- Мінімальний клікабельний розмір — 40×24 логічних (вистачає padding'у); окремих
  дрібніших кнопок не робити.

### 1.3 Коли який варіант

- **Одна дія** — вона `accent`, якщо це основна мета екрана; інакше базова.
- **Дві дії рівної ваги** — обидві базові (Fluent: «more than two buttons with
  equal priority → all neutral backgrounds»). Не роби обидві `accent`.
- **Багато дрібних/повторюваних дій** (тулбар, рядок списку) — усі `ghost`, щоб
  ряд не «шумів» (Fluent: outline/subtle/transparent to avoid a busy layout).
- **Форма з підтвердженням** — `accent` на головну («Зберегти»), базова на
  «Скасувати», ghost на допоміжне («Скинути до типових»).

### 1.4 ЗАБОРОНА мішати варіанти й дублювати primary

**У одному ряду дій — не більше однієї `accent`-кнопки.** Дві золоті поруч = дві
«головні» = ніякої ієрархії (Fluent: «only one primary button in a layout»).
Решта ряду — базові або ghost, але **однакові між собою**: не «одна базова + одна
ghost + одна accent» безсистемно. Правило ряду:

> `[ghost…] [secondary…] [PRIMARY]` — тихі ліворуч, основна праворуч (крайня).

Розміщення: **основна дія — крайня права** у право-вирівняному кластері дій
(нативна Windows-конвенція для «підтвердити»); руйнівна/скасувальна — ліворуч від
неї. Не змішувати вирівнювання дій у межах одного екрана.

### 1.5 Деструктив — патерн

```python
btn = QPushButton(tr("delete_dict"))   # danger (стриманий теракот), НЕ accent, НЕ ALERT-червона
btn.setProperty("danger", True)
btn.clicked.connect(self._confirm_delete)
# ...
def _confirm_delete(self):
    if QMessageBox.warning(self, tr("delete_title"), tr("delete_body"),
                           QMessageBox.Yes | QMessageBox.No) == QMessageBox.Yes:
        ...
```

## 2. Форми — сітка «лейбл → контрол»

### 2.1 Двоколонкова сітка, єдина вісь

Канон уже кодифікований у `settings.py:140-153` (`_grid` + `_form_label`) — його й
тримаємо як **єдиний спосіб** будувати форму. Жодних інлайн-стилів, жодних
«лейбл над контролом» вроздріб.

```python
g = QGridLayout()
g.setHorizontalSpacing(24)          # XXL — зазор колонка-лейбл ↔ колонка-контрол
g.setVerticalSpacing(12)            # M  — вертикальний ритм рядків
g.setColumnMinimumWidth(0, 168)     # _LABEL_COL — спільна вісь усіх лейблів
g.setColumnStretch(1, 1)            # контроли тягнуться вширину
# рядок:
g.addWidget(_form_label(tr("key")), r, 0)   # колонка 0 — лейбл (formlabel, 14/muted)
g.addWidget(control,                r, 1)    # колонка 1 — контрол
```

Правила:
- **Усі лейбли форми вирівняні по лівому краю колонки 0** (ширина 168px) — це і є
  «єдина вісь». Не робити лейбли різної ширини в межах однієї форми.
- Лейбл — `_form_label()` (роль `formlabel`, 14px, `TEXT_MUTED`), вирівняний по
  верху свого рядка, якщо контрол багаторядковий.
- Лейбл + ⓘ-підказка — `_labeled_hint()` (лейбл + інфо-кнопка в HBox, зазор 6),
  кладеться в колонку 0 замість голого лейбла.
- **Примітка під контролом** — окремий рядок сітки, `QLabel[muted]`,
  `setWordWrap(True)`, колонка 1 (під контролом, НЕ під лейблом).

### 2.2 Вертикальний ритм

- Крок між рядками форми — **12px** (`M`, verticalSpacing сітки).
- Між логічними групами полів — картка-секція (§3), не збільшений spacing.
- Відступ НАД групою більший за відступ ПІД нею (групування близькістю ~2:1),
  як у типографічному каноні.

### 2.3 Зовнішні поля сторінки

Root-VBox сторінки: **`setContentsMargins(32, 26, 32, 18)`** — де-факто канон (7
сторінок уже так). Нові сторінки беруть це значення, не вигадують власне.

## 3. Картки / групи

### 3.1 Картка vs плоска група

- **Картка** (`QFrame[card="true"]`, `theme.py:170-179`: фон CARD, 1px hairline,
  radius 6) — коли групу треба **візуально відокремити** від сусідів: секція
  налаштувань, елемент списку-вибору, діалог-блок. Хелпер: `_card(title, hint_key)`
  (`settings.py:116`).
- **Плоска група** (просто VBox/Grid без рамки) — коли поля вже в межах однієї
  картки/сторінки й додаткова рамка лише додасть «коробку в коробці». Не вкладати
  картку в картку без потреби (Fluent: уникати busy-вкладеності).
- Активний/обраний стан картки — золота рамка + заливка 10% (`[active="true"]`),
  не інший фон.

### 3.2 Внутрішні відступи — три тири

Сьогодні в коді ~4 різні padding'и карток (аудит: `26/22/26/20` ×9,
`18/13/18/15` ×6, `24/20/24/18` ×5, `22/18/22/20` ×1) — **консолідувати у три
свідомі тири** (застосування — окрема хвиля):

| Тир | contentsMargins | inner spacing | Для |
|---|---|---|---|
| **Секція-картка** | `24, 20, 24, 18` | 14 | групи налаштувань, діалог-блоки, `_card` |
| **Рядок списку** | `18, 14, 18, 14` | за вмістом | queue-row, entry-row, history-row |
| **Компактний чіп** | `12, 8, 12, 8` | 8 | дрібні статус-плитки |

Заголовок картки — `QLabel[level="block"]` (16/600), зазор до вмісту 14px.
Різнобій `26/22/26/20` та `22/18/22/20` зводиться до тиру «Секція-картка».

## 4. Стани й повідомлення про помилку

### 4.1 Інтерактивні стани (уже в QSS — не дублювати локально)

Кожен контрол у `theme.py` уже покриває 4 стани системно — новий контрол **не
задає їх інлайн**, а користується глобальним QSS:

| Стан | Візуальний патерн | QSS |
|---|---|---|
| hover | золота рамка 65% + текст `TEXT_STRONG` | `:hover` |
| focus (клавіатура) | суцільна 1px `FOCUS`-рамка | `:focus` |
| pressed | темніша/золота заливка | `:pressed` |
| disabled | ~45% opacity тексту + приглушений фон | `:disabled` |

Непослідовність до вирівнювання: focus-рамка `QPlainTextEdit` = 2px
(`theme.py:257`), решта 1px — привести до 1px під час застосування.

### 4.2 Помилки — три канали й де їх місце

Inline-error «червона рамка + текст під полем» у коді ще нема — **канонізуємо**:

1. **Валідація конкретного поля** → короткий текст помилки **під контролом**
   (колонка 1 сітки, НЕ під лейблом), роль `hint`, колір `ALERT_TEXT`,
   `setWordWrap(True)`, поява через `motion.slide_fade_in`. За потреби — 1px рамка
   поля кольором error-бейджа `rgba(229,36,33,0.55)` (той самий, що
   `badge="error"`, `theme.py:208`). **Повідомлення завжди поряд із полем, що його
   спричинило** — ніколи в далекому статус-барі.
2. **Блокуюча/незворотна помилка чи підтвердження** → `QMessageBox.warning`
   (основний канал: невалідний імпорт, конфлікт видалення — `settings.py:1067`
   тощо).
3. **Транзієнтний статус операції** → статус-лейбл поряд із дією (патерн тесту
   мікрофона `settings.py:52,1770`), текст із мапи вердиктів, анімована поява.

ALERT-червоний — тільки в **тексті** помилки та error-бейджі, ніколи як заливка
кнопки чи великої поверхні (канон `theme.py:5`).

## 5. Чекліст відповідності (білдеру) + автоперевірки

### 5.1 Чекліст перед комітом сторінки/діалогу

- [ ] Кнопки: у кожному ряду дій **≤1 `accent`**; решта — однаковий варіант.
- [ ] Жодного `setFixedWidth` на `QPushButton` (ширина від тексту).
- [ ] Деструктив — вторинна кнопка варіанта `danger` (стриманий теракот §1.1/§1.5, НЕ ALERT-червоний) + обовʼязковий `QMessageBox`-підтвердження.
- [ ] Форма побудована через `_grid()` + `_form_label()`; усі лейбли на осі 168px.
- [ ] Примітка/помилка — під контролом (колонка 1), `wordWrap=True`.
- [ ] Усі `setSpacing`/`setContentsMargins` — зі шкали §0 (4px; винятки 2/6).
- [ ] Картка обрана свідомо (не «коробка в коробці»); padding із тиру §3.2.
- [ ] Жодних інлайн `setStyleSheet` на кнопках/лейблах/полях — лише глобальний QSS.
- [ ] Стани (hover/focus/pressed/disabled) не переозначені локально.
- [ ] Новий контрол без видимого тексту має `accessibleName` (канон гейта).

### 5.2 Що можна винести в автоперевірку

Реалізовано зараз (дешевий статичний лінт, `tests/test_design_lint.py`):
- **Варіанти кнопок**: `setProperty("…")` на кнопках — лише з канонічної множини
  `{accent, ghost, danger}`; поява ad-hoc `primary`/`secondary`/`destructive` = провал.
- **Контракт QSS**: `theme.py` визначає рівно ці варіанти (accent/ghost/danger/базовий).

Рекомендовано додати згодом (потребує чистки коду перед увімкненням):
- **Off-grid spacing**: скан `setSpacing(N)` у `fronts/desktop` — `N` зі шкали §0
  (4-кратні + винятки 2/6); зараз блокують 1×`3`, 1×`5` — прибрати, тоді вмикати.
- **Fixed-width кнопки**: grep `setFixedWidth` поряд із `QPushButton` = провал.
- **Змішані accent у ряду**: складніше (AST-аналіз layout'у) — ловиться візуальним
  QA-гейтом (рубрика), не дешевим грепом; лишити людському огляду.
- **Inline-стилі**: `setStyleSheet` поза `theme.py`/`app.setStyleSheet` для
  кнопок/лейблів — після зачистки наявних (`main_window.py:492` del_btn тощо).

Критерій готовності канону: `test_design_lint.py` зелений у гейті; чекліст §5.1 —
частина рев'ю сторінки; застосування тирів §3.2 і шкали §0 до коду — окрема хвиля.
